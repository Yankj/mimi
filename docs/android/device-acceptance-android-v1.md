# mimi Android 真机验收清单 v1

> 对应 PLAN §6.4。**M3 起每个里程碑追加**（M3：A/D；M4：G）。本文件只记录**需要真机**才能判定的项目；JVM 内已断言的行为见各里程碑的测试表（PLAN §8.x）。
> 状态：☐ 未验 ／ ✔ 通过 ／ ✘ 失败（备注机型、系统版本、现象）。M3 的全部项目当前都是 ☐——开发机没有设备，下面每一项都是「等手机来验」。

机型信息（验收时填）：设备 ______ · Android ____ · 是否有 Google 语音服务 ____ · 语言 ____ · 日期 ____

## A 语音（M3）

| # | 项目 | 怎么验 | 预期 | 状态 |
|---|---|---|---|---|
| A1 | 首次点话筒的站内说明 | 全新安装 → 添加孩子 → 点输入卡话筒 | 先出现说明（含「继续」「改用键盘」），**此时系统还没弹权限框**；点继续后才弹 | ☐ |
| A2 | 说明文案按识别方式区分 | 看说明与「我们家 → 设置」里的「语音识别」行 | 本机识别：写「只在本机」；系统语音服务：写明「可能经系统语音服务在线识别」；都没有：写明不可用并只给键盘 | ☐ |
| A3 | 拒绝权限 | 在系统框点拒绝 | 输入卡内出现一句提示 + 「打开系统设置」+ 「改用键盘」；键盘输入照常可用 | ☐ |
| A4 | 点按听写 | 点话筒说一句「明天下午三点带团团去游泳」 | 出现胶囊：电平条 + 计时 + 实时文字；再点结束；文字留在可编辑预览里，**未保存** | ☐ |
| A5 | 按住说话 | 切到语音模式，按住胶囊 ≥0.3 秒说话 | 松手后文字进入预览；短按（<0.3 秒）不算按住 | ☐ |
| A6 | 上滑发送 | 按住后手指上滑超过约 70dp | 提示变为「松开发送」，松手后直接出确认卡 | ☐ |
| A7 | 左滑取消 | 按住后手指左滑超过约 90dp | 提示变为「松开取消」，松手后丢弃这次听写，原草稿恢复；左滑优先于上滑 | ☐ |
| A8 | 触感 | A5–A7 过程 | 开始/越过阈值/松手各有一次轻触感 | ☐ |
| A9 | 静音与超时 | 点话筒后不说话 | 约数秒后出现「没听到声音」提示并自动消失，不卡在听写态 | ☐ |
| A10 | 中断 | 听写中来电 / 锁屏 / 切后台 | 立即停止，已识别文字保留并有一句说明；**不会被偷偷保存** | ☐ |
| A11 | 耳机 / 蓝牙麦克风 | 戴耳机或连蓝牙再听写 | 能正常识别（或给出明确失败提示） | ☐ |
| A12 | 无 Google 语音服务 / 无网络 | 国内 ROM 或飞行模式 | 给出「不可用」提示并只剩键盘，不崩溃；设置里「语音识别」行如实显示 | ☐ |
| A13 | 本机识别包 | Android 12+，设置里下载/删除中文离线语音包后重试 | 有包 → 本机识别；无包 → 回落或提示，不假装可用 | ☐ |
| A14 | 麦克风隐私指示 | 听写时看状态栏 | 出现系统麦克风指示点；停止后消失（不应在后台常亮） | ☐ |
| A15 | 键盘切换与大字号 | 点键盘/波形切换；系统字体调到最大 | 切换后输入框聚焦、输入卡展开；字体 ≥1.6 倍时强制键盘且仍不遮挡底栏 | ☐ |

## D 输入卡 · 确认卡（M3）

| # | 项目 | 怎么验 | 预期 | 状态 |
|---|---|---|---|---|
| D1 | 空闲布局 | 有孩子时看「今天」「成长」 | 底栏之上有输入卡（+ ／ 键盘 ／ 按住说话）；「我们家」和没有孩子时不出现 | ☐ |
| D2 | + 菜单 | 点 + | 「手动记一件安排」「手动记一条观察」，放在语音之后 | ☐ |

| D4 | 确认 | 点确认 | 保存中 → 回执，约 1.6 秒后自动收起；今天/成长里出现这条 | ☐ |
| D5 | 关闭放弃 | 在确认卡点 × | 无任何写入 | ☐ |
| D6 | 缺字段追问 | 输入「带团团去游泳」（没说时间） | 只问一个问题；回复后再出确认卡 | ☐ |

| D8 | 改期 | 对已有安排说「把游泳改到周日下午三点」 | 确认卡显示改前/改后；确认后只改那一条 | ☐ |
| D9 | 手动调整回流 | 确认卡上点「手动调整」 | 打开空白手动表单（不预填，与 iOS 一致），未保存即放弃 = 零写入 | ☐ |
| D10 | 软键盘 | 输入时弹出软键盘 | 输入卡跟随键盘上移，不被遮挡；确认卡按钮不被键盘盖住 | ☐ |
| D11 | TalkBack | 开启 TalkBack 走 A4、D3、D4 | 话筒/按住/确认卡有朗读；回执**不应**因自动收起而来不及读（待 M8 无障碍审计最终定） | ☐ |

## G 本机提醒（M4）

> 提醒只在本机：AlarmManager + 通知，不经服务器、不写系统日历。规则与 iOS 一致：只提醒**已确认**的安排；每天最多 2 条；21:00–08:00 勿扰（落在勿扰里的改到前一晚 20:30）；提前量 15 分钟 / 30 分钟 / 1 小时（默认）/ 前一晚 20:00。下面全是真机才能判定的项。

| # | 项目 | 怎么验 | 预期 | 状态 |
|---|---|---|---|---|
| G1 | 先说明、后权限 | Android 13+，全新安装 → 加孩子并确认一件未来的安排 → 「今天」出现「让小咪在开始前提醒你」卡 → 点「开启提醒」 | 打开 App 时**不会**自己弹通知权限；点「开启提醒」后才弹系统框；允许后卡片消失，该安排下出现「将在 … 提醒」 | ☐ |
| G2 | 拒绝通知权限 | G1 的系统框点「不允许」 | 「今天」出现「系统通知已关闭，小咪现在无法提醒你」+「打开系统设置」；其余功能照常；账本改动不受影响 | ☐ |
| G3 | 从系统设置回来自动补排 | G2 后点「打开系统设置」→ 打开通知 → 返回 App | 红色提示消失，安排下出现「将在 … 提醒」，「我们家 → 提醒」里显示已排数量 | ☐ |
| G4 | 精确闹钟权限（Android 12+） | Android 14+ 默认**未授予**；看「我们家 → 提醒」 | 未授予时写明「没有『闹钟和提醒』权限，提醒可能晚几分钟才到」并有「打开闹钟和提醒设置」；授予后回到 App 提示消失 | ☐ |
| G5 | 到点真的响 | 建一件 20 分钟后的安排，提前量 15 分钟，确认后锁屏等 | 约 5 分钟后锁屏上出现「小咪提醒」通知（精确闹钟：准点；否则允许晚几分钟）；标题/正文含孩子与事项（隐藏内容未开时） | ☐ |
| G6 | 点通知回到 App | 点 G5 的通知 | 打开 App 并停在「今天」页（Android 版没有安排详情页，与 iOS 一样不做额外跳转）；App 已在前台/后台/被划掉三种状态都试 | ☐ |
| G7 | 锁屏隐藏内容 | 「我们家 → 提醒」打开「锁屏上隐藏孩子和事项」，再触发一次提醒 | 通知只显示「有一件孩子的安排即将开始，打开小咪查看」 | ☐ |
| G8 | 勿扰与每天 2 条 | 同一天确认 3 件安排（提醒时间都在白天） | 第 3 件显示「未提醒：当天已有 2 条提醒」；把一件安排改到 22:00 → 提醒改到前一晚 20:30，并有说明 | ☐ |
| G9 | 改期/完成/删除/取消会撤掉提醒 | 对有提醒的安排依次：改期、完成、删除、取消 | 旧提醒不再响；改期后按新时间排；「我们家 → 提醒」的已排数量同步 | ☐ |
| G10 | 重启后重排 | 开着提醒、有一件未来安排 → 手机重启（**重启后不要打开 App**） → 等到点 | 到点仍然响（BOOT_COMPLETED 触发重排）。**国产 ROM 常禁止应用开机自启：不响则记下机型，见 G13** | ☐ |
| G11 | 时区/校时 | 把系统时区改到另一个时区，或手动改时间，再回 App | 提醒按新时区的「勿扰/当天」重新排；不会重复响 | ☐ |
| G12 | 更新应用后仍在 | 用 `adb install -r` 覆盖安装 | 已排提醒仍有效（MY_PACKAGE_REPLACED 重排） | ☐ |
| G13 | 省电/后台限制 | 在小米/华为/OPPO/vivo 等省电严格的机型上，把 App 划掉、锁屏等待；再把 App 加入电池优化白名单重试 | 如实记录：划掉后是否仍响；白名单后是否改善。页面里的「打开电池优化设置」要能跳到系统页 | ☐ |
| G14 | Doze 深度休眠 | 手机静置一晚（或 `adb shell dumpsys deviceidle force-idle`），有一条夜间前的提醒 | 非精确闹钟在 Doze 里可能延迟若干分钟（记录延迟）；精确闹钟应更准 | ☐ |
| G15 | 退出登录/清除数据 | 「设置 → 退出登录」，或「清除全部数据」 | 已排提醒与锁屏上已送达的通知都被清掉，不会再响；清除数据保留提醒开关，退出登录则重置 | ☐ |
| G16 | 设备端检查 | `./gradlew :core:device:connectedDebugAndroidTest`（日志 tag `MimiReminders` 打印授权与精确闹钟状态） | 通过；把日志里的状态写回 G2/G4 备注 | ☐ |

## H 云端账号与「让小咪整理」（M5）

> 需要**已配置云端**的构建（本机 `local.properties` 填好 Supabase 地址、anon key、后端地址后自行构建）；交付的 `mimi-m5-debug.apk` 是未配置构建，只能验 H1。OAuth 还需 Supabase 允许列表里有 `catpawm://auth-callback`。

| # | 项目 | 怎么验 | 预期 | 状态 |
|---|---|---|---|---|
| H1 | 未配置 = 离线 | 装未配置 APK → 设置 → 账户 | 只显示「体验账号」「仅保存在这台手机上」「退出登录」；没有登录入口；「记一件安排」里没有「让小咪整理」；飞行模式下一切照常 | ☐ |
| H2 | 邮箱注册 | 设置 → 登录或注册 → 填邮箱与 ≥8 位密码 → 注册 | 需要确认时提示「请先在邮箱里确认注册，再登录」；确认后再登录成功，设置显示邮箱 | ☐ |
| H3 | 邮箱登录与错误 | 错密码登录；再正确登录 | 错密码：「邮箱或密码不正确。」；正确：浮层自动关闭 | ☐ |
| H4 | 体验账号 | 登录浮层 → 无需注册，即刻开始 | 设置显示「体验账号」；若项目未开匿名登录，提示「体验账号暂未开放，可以用邮箱登录。」 | ☐ |
| H5 | Google / GitHub | 点「使用 Google 继续」/「使用 GitHub 继续」 | Custom Tabs 打开授权页 → 授权后回到 App 已登录；取消授权回到 App 不报错；允许列表缺失时授权页报错（记录原文） | ☐ |
| H6 | 本机数据带入第一个账号 | 未登录时加一个孩子 → 登录 | 孩子仍在；退出登录 → 孩子消失（与 M2 退出一致）；再登录另一个账号 → 空 | ☐ |
| H7 | 冷启动保持登录 | 登录后强行停止再开 | 仍是登录状态（真 AndroidKeyStore 解密令牌）；令牌过期后再用整理功能会自动续期 | ☐ |
| H8 | 让小咪整理 · 发送许可 | 记一件安排 → 填原话「明天下午三点带孩子去游泳」→ 让小咪整理 | 先出发送许可说明（来自服务端）；点「暂不允许」不发送；点「允许」后显示「小咪正在整理…」 | ☐ |
| H9 | 候选与采用 | H8 允许后等待 | 出现「整理建议 · 尚未采用或保存」；点「采用整理结果」才填入名称和时间；不点保存就关闭 → 不入账 | ☐ |
| H10 | 弱网 / 切后台 | 整理中开飞行模式或切后台 | 显示结果未确认 +「检查本次结果」「停止等待本次整理」；联网后「检查本次结果」只读回读，**不会重复发送** | ☐ |
| H11 | 冷恢复 | 整理中强行停止 → 重开 → 再打开记一件安排 | 出现「恢复上次整理」；恢复只读，不会再发模型请求 | ☐ |
| H12 | 清理 | 采用/删除本次整理记录 | 云端临时会话被删除；断网时显示「本次临时整理记录尚未完成清理」+「重试清理」，此时不能发起新整理 | ☐ |
| H13 | 邀请码 | 邮箱账号未开通 → 设置 → 输入邀请码 | 错码「邀请码无效…」；多次错码「尝试次数过多…」；正确后显示「已开通」 | ☐ |
| H14 | 退出登录 | 设置 → 退出登录 | 回到未登录；服务端撤销失败时提示「已在此设备退出；服务端会话撤销未确认。」；本机提醒一并清除 | ☐ |
